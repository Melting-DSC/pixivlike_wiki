CONTENT GUIDE

編集ガイド

このサイトは、3つのJSONファイルと小さなビルドスクリプトで動いています。 文章・画像・カテゴリ・項目数はすべてデータから生成されるので、HTMLを直接編集する必要はありません。

クイックスタート

Node.js 18以降を用意して、プロジェクトのルートで次を実行します。

terminalbash
npm run dev

表示されたURLをブラウザで開きます。

記事ページ相対パス: index.html コンテンツエディタ相対パス: editor.html
コマンド動作
npm run devローカルサーバーを起動し、content/ の変更を監視して自動ビルドします。
npm run buildindex.html を一度だけ再生成します。
npm startnpm run dev と同じです。
npm run preview監視なしで静的ファイルを配信します。
ビルドはNode.jsだけで動きます。

npm installは不要です。外部ライブラリやビルドツールは使っていません。

エディタの使い方

コンテンツエディタは、フォームとJSONを同じ内容で編集できるローカル専用ツールです。 左のナビゲーションから「基本情報」「本文」「カテゴリ」「サイト設定」「JSON」を切り替えます。

  1. フォームで編集するタイトル、概要、本文ブロック、カテゴリ、フッターなどを入力します。
  2. 「保存してビルド」を押す3つのJSONが保存され、その場で index.html が再生成されます。
  3. 記事を再読込する別タブで index.html を開いている場合は再読み込みしてください。

できること

  • 本文セクションとブロックの追加・削除・並べ替え。
  • カテゴリグループと収録項目の追加・削除・並べ替え。
  • JSONタブで直接編集し、構文を確認してから反映。
  • 3ファイルをZIPで書き出し、または手元のJSONを読み込んで復元。
  • Ctrl / Cmd + S で保存。
保存はローカルサーバー専用です。

エディタの保存機能は npm run dev の POST /api/save を使います。 静的ホスティング上では保存できないため、「書き出し」でZIPを取得し、content/ に上書きしてから npm run build を実行してください。

保存時にJSONの検証やビルドが失敗した場合、3ファイルは保存前の状態へ自動的に戻ります。 安心して編集できますが、大きな変更の前には「書き出し」でバックアップを取っておくと確実です。

データ構造

編集するファイルは次の3つです。すべてUTF-8のJSONで、コメントは書けません。

content/site.json

サイト名、パロディ表記、注意バー、ヘッダー、注目リンク、フッター、モバイルメニュー。

content/article.json

記事タイトル、概要、パンくず、本文セクション、関連タグ、編集履歴、リンク語句。

content/categories.json

カテゴリ一覧の見出しと、カテゴリグループ・色・説明・収録項目。

article.json の主なキー

キー内容
title / reading記事タイトルと読み。ページタイトルにも使われます。
summaryタイトル下の短い説明。meta descriptionにもなります。
breadcrumb{ label, href } の配列。記事名は自動で末尾に付きます。
categories記事ヘッダーに出すカテゴリ名の配列。categories.json のグループ名と対応させます。
heroヒーロー画像。src, alt, caption, credit, creditHref。
actions記事ヘッダーのリンク。label, href, primary。
updated / version最終更新日とバージョン表記。
linkTerms[[語句]] のリンク先をまとめたオブジェクト。
sections本文セクションの配列。id, level, title, blocks。
relatedTags関連タグの配列。サイドバーと検索に使われます。
history{ date, note } の配列。編集履歴ダイアログに表示。
about「このサイトについて」の見出しと本文。

セクションの level は 2 が大見出し、3 が小見出しです。 id は目次アンカーになるため、ファイル内で重複させないでください。

categories.json の構造

categories.jsonjson
{
  "title": "カテゴリ一覧",
  "description": "一覧の説明文",
  "groups": [
    {
      "id": "general",
      "name": "一般",
      "color": "#5b7c99",
      "description": "グループの説明",
      "items": [
        { "name": "C言語", "href": "#top", "current": true },
        { "name": "未作成の項目", "soon": true }
      ]
    }
  ]
}

current: true を付けた項目には「この記事」バッジが付きます。 soon: true は未作成項目として、クリック時に案内を表示します。 href を省略した場合はカテゴリ一覧へのリンクになります。

site.json の主なキー

キー内容
siteサイト名、PARODY バッジ、ロゴ、説明、テーマ色、言語。
notice画面上部の注意バー。表示可否と保存キー。
header検索欄、投稿ボタン、ログインボタンの文言とリンク。
spotlight「注目」リンク。query を指定すると検索、href なら通常リンク。
footer紹介文、リンク列、著作権表記、免責事項。
menuモバイル用ドロワーの見出しとリンク。

本文ブロック

sections[].blocks[] には、次の type を指定します。 ブロックの順番がそのまま本文の順番になります。

type主なキー表示
paragraphtext段落。
listtitle, items[], ordered箇条書き。ordered: true で番号付き。
codelanguage, filename, codeコピーボタン付きのコードブロック。
callouttone, title, text注記。tone は info / warn / parody。
tagsitems[]押すと検索できるタグクラウド。
figuresrc, alt, caption, credit画像とキャプション。
quotetext, cite引用ブロック。
dividerなし区切り線。
article.json（抜粋）json
"sections": [
  {
    "id": "overview",
    "level": 2,
    "title": "概要",
    "blocks": [
      { "type": "paragraph", "text": "本文です。[[C++]] にも触れます。" },
      {
        "type": "callout",
        "tone": "info",
        "title": "補足",
        "text": "ここはパロディです。"
      }
    ]
  }
]

未対応の type はビルド時に警告され、生成HTMLにはコメントとして残ります。 エディタのブロック種別セレクタを使えば、必要なキーを自動で用意できます。

インライン記法

段落、リスト、注記、引用、キャプションでは、次の記法が使えます。

書き方結果
[[C++]]linkTerms のリンク先を使って「C++」をリンク。
[[C++|Cプラプラ]]表示名だけ変えてリンク。
[ラベル](https://example.com)通常のリンク。外部URLは新しいタブで開きます。
**強調**太字。
`コード`インラインコード。
[[語句]] のリンク先

article.json の linkTerms にURLや #アンカー を登録します。 未登録の語句は平文で表示され、ビルド時に警告が出ます。

HTMLタグはエスケープされ、そのままでは埋め込まれません。コードブロック内の code も そのまま表示されるため、インライン記法は適用されません。

画像

画像は assets/images/ に置き、assets/images/ファイル名 の相対パスで参照します。 SVG、PNG、JPEG、WebP、GIFに対応しています。

  • article.hero は記事上部の大きな画像です。
  • figure ブロックは本文中の画像です。
  • ローカル画像のパスが存在しない場合、ビルドはエラーで停止します。
  • 外部URLと data: URLは存在チェックの対象外です。

画像には内容を説明する alt を付け、出典がある場合は credit に記載してください。 現在のロゴと挿絵は、このパロディ用に作成したオリジナルのSVGです。

自動計算されるもの

次の値は手で書かず、ビルド時にデータから計算されます。

  • 節番号：level: 2 で大番号、level: 3 で小番号が進みます。
  • 本文ブロック数：全セクションの blocks の合計。
  • カテゴリ数：categories.groups の数。
  • 収録項目数：各グループの items の延べ数。重複を除いた数も内部で計算します。
  • 関連タグ数：article.relatedTags の数。
  • 検索インデックス：セクション本文、カテゴリ、タグから生成。
数字を直接HTMLに書かない

サイドバーの「全◯項目（延べ）」のような表示は、categories.json を変えれば自動で更新されます。 手作業で数え直す必要はありません。

公開と書き出し

生成物はルートの index.html です。CSS、JavaScript、画像、ガイドを含めて、 次のファイルを静的ホスティングにアップロードすれば公開できます。

公開するファイルtext
index.html
guide.html
editor.html
assets/
content/

content/ はエディタが読み込むために必要です。エディタを公開しない場合は省略できますが、 その場合でも再ビルド用にリポジトリ側で保管してください。

静的ホスティングで更新する流れ

  1. エディタで編集する「書き出し」を押し、pixpedia-content.zip を取得します。
  2. JSONを上書きするZIP内の3ファイルを content/ に置きます。
  3. ビルドするnpm run build で index.html を再生成します。
  4. アップロードする変更したファイルをホスティングへ転送します。

注意事項

  • index.html は生成物です。直接編集しても次のビルドで上書きされます。
  • JSONの構文エラーや必須項目の不足は、ビルド時に日本語のエラーとして表示されます。
  • セクションIDとカテゴリIDは重複させないでください。
  • 大きな変更の前には、エディタの「書き出し」でバックアップを取ってください。
  • このサイトは「ピクシブ百科事典」の外観を参考にした非公式パロディです。実在の記事・画像・ロゴとは関係ありません。
  • 検索避けのため、全HTMLページに noindex を指定し、robots.txt でクロールを拒否しています。GitHub Pages は公開状態のままなので、アクセス制限ではありません。
